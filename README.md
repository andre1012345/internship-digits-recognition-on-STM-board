# MNIST Digit Recognition on STM32N6570-DK

Real-time handwritten digit recognition (0–9) running entirely on the **STM32N6570-DK**: the IMX335 camera captures the scene, a preprocessing step in C cleans the image, and a small int8 CNN classifies it on the **Neural-ART NPU** in ≤ 1 ms. The result is shown on the LCD and printed over UART.

**Status (2026-10-19):** working end-to-end. With the vignetting-robust preprocessing (`PREPROC_MODE 1`) and correct framing, **9 of 10 MNIST digits shown on a monitor are recognised on 100% of frames (89% overall frame accuracy)**; the only remaining error is one sample of digit 9 read as 8. Progression over the day: 40% → 75% → 82% → 89%. Details in [`Doc/test-results.md`](Doc/test-results.md).

## From a fresh clone to a running board

### What you need

| | |
|---|---|
| Board | **STM32N6570-DK** with the **IMX335 camera module** connected (flat cable to the camera connector) |
| PC | Windows, USB-C cable (data, not charge-only) |
| STM32CubeIDE | tested with **2.1.1** |
| STM32CubeProgrammer | **≥ 2.18**, installed in the **default path** `C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer` — used by `flash.ps1` *and* by the build to sign the binary |
| Serial terminal | PuTTY or the CubeIDE terminal |

### Boot switches

| Mode | BOOT0 | BOOT1 | Used for |
|---|---|---|---|
| **Boot from flash** | left (L) | left (L) | normal operation |
| **DEV mode** | left (L) | **right (H)** | flashing and debugging |

| Boot from flash | DEV mode |
|---|---|
| ![Boot from flash](Doc/ST-reference/_htmresc/STM32N6570-DK_Boot_from_flash.png) | ![DEV mode](Doc/ST-reference/_htmresc/STM32N6570-DK_Dev_mode.png) |

The switches are read only at power-up: **unplug and replug USB after every change** (the reset button is not enough).

### 1. Get the code

```powershell
git clone https://github.com/andre1012345/STM32N6-digits-recognition.git C:\Dev\STM32N6-digits-recognition
```

Use a short path without spaces: Windows has a 260-character path limit and the ST libraries are deeply nested.

### 2. Import the project in STM32CubeIDE

1. **File → Import… → General → Existing Projects into Workspace → Next**.
2. *Select root directory*: `<clone>\Application\STM32CubeIDE`.
3. Tick `STM32N6570-DK_GettingStarted_ImageClassification`. Leave **"Copy projects into workspace" unticked** — the project must stay in the clone, `flash.ps1` looks for the binary there.
4. **Finish**.

If CubeIDE says the project "already exists in the workspace", remove the old entry first (right-click → Delete, **without** "Delete project contents on disk").

### 3. Build

Right-click the project → **Build Project**. The post-build step signs the image and produces
`Application/STM32CubeIDE/Debug/Project_sign.bin`. The console must end with `Build Finished. 0 errors`.

### 4. Flash

Set the board to **DEV mode** (BOOT1 right), connect USB to **CN6** (ST-LINK), replug. Close STM32CubeProgrammer if it is open. PowerShell in the clone folder:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\flash.ps1 -Weights    # new or erased board: bootloader + application + model weights (~30 s)
.\flash.ps1 -AppOnly    # later, after a code change: application only
```

Each of the three steps must report `File download complete`.

### 5. Run

Set the switches to **boot from flash** (both left) and replug USB. Open the ST-LINK serial port (Device Manager → *Ports* → *STLink Virtual COM Port*), **115200** baud, 8N1:

```
[HW] UART OK … [HW] XSPI NOR OK
MNIST Digit Classification - STM32N6570-DK
[3] 99%  (0ms)
```

The LCD shows the camera image with the predicted digit and the confidences.

### Alternative: run from the debugger (no flash write)

Useful while developing. The weights must already be in flash (step 4 with `-Weights`, once).
Board in **DEV mode**, replug → right-click `STM32N6570-DK_GettingStarted_ImageClassification.launch` → **Debug As** → **STM32 C/C++ Application** → the program stops at `main()` → **Resume (F8)**. The application runs from RAM and is lost at power-off.

### Using it

Hold a digit (dark ink on white) **10–15 cm** from the camera:

- the digit must be centred and **fully inside the frame**, with only white paper/screen around it — a paper border or monitor edge in view is read as an extra stroke (e.g. 7 → 3);
- keep the camera still (rest the board against something);
- predictions with low confidence (< 70%) on an empty or moving scene are normal: treat them as "no digit".

## How to run a measured test

The procedure used for the results in `Doc/test-results.md`:

1. **Target:** the *MNIST Test Card* web page shows real MNIST digits 0→9 full-screen, black on white: 5 s lead-in, then 10 s per digit + 2 s blank (sets A, B, C = different handwriting samples).
2. **Logging:** PuTTY saved session `board` → *Session → Logging → All session output* → file in `Doc\logs\` with the date and test number in the name (e.g. `2026-10-19_test4.txt`). Load the session, set a new file name, **Save**, then **Open**.
3. **Framing:** camera 10–15 cm from the monitor, only the white page visible around the digit, board held still.
4. Start the page; the UART log (≈15 predictions/s) is then split into 12 s slots, one per digit, and each slot is scored (majority prediction, % of correct frames, mean confidence).
5. With `DEBUG_DUMP_MS` enabled the log also contains, every 2 s, the camera image and the exact network input as ASCII art — use it to see *why* a digit is misread.

## Firmware settings (top of `main.c`)

| Define | Default | Meaning |
|---|---|---|
| `TEST_MODE` | `0` | `1` = cycle through the images in `digits.h` instead of the camera |
| `PREPROC_MODE` | `1` | `0` = original global threshold; `1` = local background subtraction (robust to lens vignetting) |
| `PREPROC_BG_RADIUS` | `6` | background window = 13×13 px |
| `PREPROC_MIN_CONTRAST` | `0.06` | residuals below this are treated as background |
| `PREPROC_STRETCH` | `0.7` | contrast stretch of the strokes |
| `DEBUG_DUMP_MS` | `2000` | every N ms print camera image and network input as ASCII art on UART; `0` = off (set to `0` for a clean demo output) |

## Model

| Property | Value |
|---|---|
| Architecture | 3× Conv2D + GlobalAvgPool + 2× Dense |
| Parameters | 28 394 — weights 27.6 KB int8 (110.9 KB in float32) |
| Input / output | 32×32×3 int8 (scale 1/255, zp −128) / 10 classes int8 (scale 1/256, zp −128) |
| Training | MNIST + augmentation (rotation, shift, zoom, shear) |
| Toolchain | Keras → ONNX → STEdgeAI (per-channel int8) → Neural-ART |
| Inference time | ≤ 1 ms on the NPU; ~15 frames/s end-to-end |

## Troubleshooting

| Symptom | Fix |
|---|---|
| Nothing on UART, screen off | Switches in DEV mode → set both to the left and replug USB |
| `[ERROR] NOR flash blank` | Weights missing → `.\flash.ps1 -Weights` |
| Debugger: "No device found on target" | Board not in DEV mode → BOOT1 right, replug USB |
| `assertion … CameraPipeline_Init` | Camera not detected → power off, reseat the camera flex cable at both ends, rebuild from clean sources |
| Build error about `STM32_SigningTool_CLI.exe` | STM32CubeProgrammer is not in the default path (see `Application/STM32CubeIDE/makefile.targets`) |
| Project "missing .project" / cannot be opened | Re-import it (step 2) after deleting the stale workspace entry |
| `.\flash.ps1` not recognised | PowerShell is not in this folder |
| Wrong digit, always the same one | Check framing (no monitor edge or paper border in view); use `DEBUG_DUMP_MS` to see what the network receives |
| Grey blobs in the corners of the network input | Lens vignetting → make sure `PREPROC_MODE` is `1` |
| PuTTY log file not created | The saved session still points to an old path → update *Logging* and **Save** the session |
